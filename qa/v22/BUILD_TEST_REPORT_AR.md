# تقرير بناء واختبار — MANGA VIRUS V22

## ما تم
- إعادة تصميم الواجهة في flavor `dev` (app/src/dev/res) + تعديلات Kotlin محدودة: MainActivity (صف الشعار/البحث/الجرس + اختصارا HOME/SETTINGS)، HomeController (الرئيسية Compose)، NeonDownloadPanel و DownloadCenterActivity (التنزيلات + الشريط السفلي).
- الشاشات: الرئيسية، المكتبة، المصادر/التصفح، البحث، التحديثات، تفاصيل المانجا، الفصول، التنزيلات: أُعيد تصميمها بتخطيطات/أحجام/خلفيات جديدة.
- القارئ والإعدادات: تأخذ الهوية الجديدة عبر إعادة ربط الألوان والخلفيات القديمة (v13/v19/v21) بقيم V22 — لم تُعد هيكلتها بالكامل.
- الملفات الأصلية لقاعدة البيانات والمصادر والتنزيل والقراءة والترجمة لم تُعدَّل (تم التحقق بمقارنة diff مع النسخة الأصلية: الفروقات خارج dev/res هي 5 ملفات Kotlin/Gradle + ids.xml + نصوص v22 + صورتا webp).
- لم يتغير package name ولا applicationId؛ مُعرّفات العناصر (ids) محفوظة (يتحقق منها الفاحص).
- الألوان والاسم تنطبق على كل المصادر لأن القوالب عامة وتعرض بيانات التطبيق الحقيقية.

## ما تم التحقق منه (ثابت فقط)
- `python3 -I qa/v22/check_resources.py proj <baseline>` → 0 أخطاء، 0 تحذيرات (XML سليم، كل المراجع تُحل، كل ids الأصلية موجودة بنفس نوع العنصر).
- توازن الأقواس في ملفات Kotlin المعدلة.
- qa/static_integration_checks.py → 10/10.

## لم يتم التحقق منه (غير متاح في بيئة العمل: لا Android SDK ولا Java ولا شبكة)
- لم يُجرَ بناء Gradle، ولم يُنتج APK (ARM64 أو غيره)، ولم يُوقَّع، ولا تحقق من التوقيع.
- لم يُختبر على محاكي أو هاتف؛ لا لقطات شاشة للتطبيق الفعلي.
- لم تُشغَّل اختبارات الوحدة. قد تظهر أخطاء ترجمة Kotlin/Compose لم يكشفها الفحص الثابت.
- qa/v21/validate_visual_alignment.py قديم ويتوقع قياسات V21، لذا يفشل عمداً بعد إعادة التصميم.

## فروقات عن الصور المرجعية
- الإعدادات تُفتح كشاشة فرعية فلا يظهر الشريط السفلي فيها؛ القارئ والإعدادات بإعادة تلوين لا إعادة بناء.
- لا تبويبات «مكتبتي» ولا شرائح فئات التصفح الموجودة في الصورة سوى ما كان موجوداً وأُعيد تنسيقه.
- صفوف الرئيسية سُمّيت بما تعرضه البيانات فعلاً (لا «الأكثر شعبية/مقترح» لأنها غير موجودة).
- نسخ layout المخصصة للشاشات الأفقية/الكبيرة (land/sw600dp) لم تُعاد تصميمها.
- لم تُستخدم أي بيانات وهمية.

## للبناء لاحقاً
`./gradlew assembleDevRelease` (أو assembleDebug) مع ABI arm64-v8a على جهاز فيه Android SDK، ثم `apksigner verify`.
