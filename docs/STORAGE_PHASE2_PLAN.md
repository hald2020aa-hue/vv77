# المرحلة الثانية — دفعة التخزين الأولى (مرشحة للبناء)

## النطاق المنفذ
- واجهة قراءة فقط، مدخلها زر التخزين في الرئيسية مؤقتًا لأن شريط dev السفلي يحوي خمسة عناصر بالفعل. لم تُحذف أي وجهة. اختيار موضع التبويب الدائم في مرحلة لاحقة.
- مدير واحد داخل DownloadManager، يستخدم DownloadProvider وDownloadCache الموجودين، ولا يكتب إلى قاعدة البيانات ولا يطلب تحديث المصدر. حساب الحجم على Dispatchers.IO، بقراءة ملفات الفصول المعروفة ومجلداتها أو ملفات CBZ، واستبعاد تكرار مسارات URI. يستخدم إشارة مراجعة من cache للتحديث عند تغيّر التنزيلات، مع زر إعادة مسح.
- العرض يعرض العدد والحجم الإجمالي، أغلفة الأعمال، الفصول المطابقة، مرشح الوسوم الأصلية الصريحة (manga/manhwa/manhua) فقط؛ الوسوم المتعارضة وغير المعروفة تبقى غير مصنفة. فتح القارئ باستدعاء ReaderActivity الحالي. متابعة القراءة تختار أول فصل غير مقروء من الفصول المحلية وفق ترتيب المصدر، لا تُعدّل إعدادات ترتيب المكتبة.
- الحساب يقتصر على الفصول المطابقة لأعمال موجودة بقاعدة البيانات ومصادر مثبتة؛ المجلدات اليتيمة أو مصادر محذوفة لا تدخل المجموع؛ لا يدّعي قياس المساحة الفعلية المخصصة على القرص. الفئات محفوظة في النموذج للدفعة التالية، ولم تُعرض بعد. لم تُختبر صحة الأحجام على SAF أو بطاقة SD أو القراءة دون إنترنت.
- لم يُنفّذ الحذف أو التحديث الشبكي أو التصنيف اليدوي أو واجهة إدارة الفئات في هذه الدفعة. لا أزرار شكلية لهذه الوظائف. لم يُغيّر schema أو version أو مصدر أو ترجمة أو تنزيل أو سجل. لم يُغيّر signing أو applicationId.

## خطة الهجرة — للموافقة قبل تنفيذها
قاعدة البيانات الحالية `tachiyomi.db` إصدار 20 باستخدام StorIO وSupportSQLiteOpenHelper. جدول `mangas` ومفتاحه `_id` وطبقة MangaTypeMapping/Resolvers موجودة. المقترح: إصدار 21 وحقل `storage_manual_type TEXT NULL`؛ `NULL` يعني تصنيف المصدر، القيم الصريحة `MANGA`, `MANHWA`, `MANHUA`, و`UNCLASSIFIED` تعني اختيارًا يدويًا. إضافة الحقل إلى createTableQuery وإلى onUpgrade بشرط oldVersion < 21، باستخدام ALTER TABLE ADD COLUMN فقط دون حذف أو إعادة إنشاء أي جدول. تحديث mapper وMangaImpl وعمليات التحديث الجزئي والنسخ الاحتياطي والاستعادة؛ الحقل لا يُكتب في تحديث بيانات المصدر ولا يُستبدل بقيمة NULL عند استعادة نسخة أقدم فوق اختيار موجود. يجب مراجعة جميع مسارات الكتابة العامة للتأكد من عدم محو اختيار أحدث أثناء حفظ كائن قديم. يجب حجز رقم ProtoNumber غير مستخدم بعد مسح مستودع نماذج النسخ الاحتياطي بالكامل. لا يتم تنفيذ أي من هذه الخطوات قبل الموافقة.

اختبارات الهجرة المطلوبة: نسخة من قاعدة حقيقية على جهاز اختبار منفصل بعد نسخ احتياطي؛ مقارنة كل الجداول قبل وبعد باستثناء الحقل الجديد، integrity_check وforeign_key_check، تحديث المصدر، إعادة تشغيل، استعادة ملف قديم وجديد؛ إثبات بقاء المكتبة والسجل والمفضلة والفئات والتتبع والتنزيلات. لا ترسل قاعدة بيانات شخصية في المحادثة؛ يمكن تشغيل الاختبار على جهازك محليًا. لا اختبار حقيقي الآن لعدم توفر قاعدة اختبار أو جهاز.

## المرحلة التالية بعد التحقق والموافقة
إضافة تبويب رئيسي مستقل بلا إزالة الخيارات، عرض الفئات والحجم ونسبه (مع بيان التداخل عند تعدد الفئات)، تأكيدات الحذف وإلغاء التنزيل الجاري بشكل متزامن قبل الحذف والتحقق من الملفات، تحديث الفصول عند فتح العمل من التخزين فقط، اختبار الجهاز والاتصال/عدم الاتصال. الحذف الحالي في DownloadManager غير متزامن ويحتاج مراجعة خاصة قبل استعماله لهذا الغرض.
